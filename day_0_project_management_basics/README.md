# Day 00: Project Fundamentals

## What I Learned

### 1. What Is a Project?

A project is a temporary effort undertaken to create a unique product, service, or result. A project has a defined objective, duration, beginning, and end.

### 2. Project vs Operations

I learned the difference between projects and operations.

* Projects are temporary and have a specific objective.
* Operations are continuous and repetitive activities.

### 3. Project Objectives

I learned that project objectives define what a project is expected to achieve. They provide measurable outcomes, align the team, and help evaluate project success.

### 4. Project Success

I learned that project success can be evaluated using factors such as:

* Scope
* Time
* Cost
* Quality
* Customer satisfaction

### 5. Project Stakeholders

I learned about the different people and groups involved in a project, including:

* Project Sponsor
* Project Manager
* Project Team
* Customer
* Users
* Management
* Vendors

### 6. Project Requirements

I learned that requirements describe the features, functions, and needs that a project must fulfill.

Examples include:

* User registration
* User login
* Dashboard
* Payment system
* Email notifications

### 7. Project Scope

I learned that project scope defines what work and deliverables are included in a project.

I also learned the difference between:

* In Scope: Work included in the project.
* Out of Scope: Work not included in the project.

### 8. Project Deliverables

I learned that deliverables are the outputs produced during a project.

Examples include:

* Requirements document
* UI design
* Developed product
* Test report
* Production release

### 9. Work Breakdown Structure

I learned how a project can be divided into smaller phases and tasks.

A project can include areas such as:

* Planning
* Design
* Development
* Testing
* Deployment

Each area can be further divided into smaller tasks.

### 10. Project Phases

I learned the main phases of a project:

1. Initiation
2. Planning
3. Execution
4. Monitoring and Control
5. Closure

### 11. Project Milestones

I learned that milestones represent important points or achievements during a project.

Examples include:

* Requirements completed
* Design completed
* Development completed
* Testing completed
* Project launch

### 12. Project Schedule

I learned how project activities can be planned over a specific period.

A schedule helps define:

* Activities
* Duration
* Sequence of work
* Total project duration

### 13. Project Resources

I learned about different resources required to complete a project.

These include:

* People
* Technology
* Financial resources

### 14. Project Budget

I learned how project costs can be divided into different categories and combined to calculate the total project budget.

Examples of budget categories include:

* Development
* Design
* Testing
* Infrastructure

### 15. Project Risks

I learned that risks are uncertain events that may affect a project in the future.

Examples include:

* Requirement changes
* Resource unavailability
* Technical problems
* Budget increases
* Schedule delays
* Security issues

### 16. Risk Register

I learned how project risks can be documented using information such as:

* Risk description
* Probability
* Impact
* Response

### 17. Project Issues

I learned that an issue is a problem that has already occurred and requires attention.

An issue can include information such as:

* Issue ID
* Description
* Priority
* Status
* Owner

### 18. Risk vs Issue

I learned the difference between a risk and an issue.

* Risk: Something that may happen in the future.
* Issue: A problem that has already happened.

### 19. Project Dependencies

I learned that some project activities depend on the completion of other activities.

For example:

* Design may need to be completed before development.
* Development may need to be completed before testing.
* Testing may need to be completed before release.

### 20. Project Communication

I learned about different types of communication during a project.

Examples include:

* Daily team meetings
* Weekly project meetings
* Stakeholder reviews
* Management reports

### 21. Project Quality

I learned that quality involves ensuring that project work and deliverables meet the required standards.

Quality activities can include:

* Defining standards
* Reviewing requirements
* Testing deliverables
* Tracking defects
* Validating the final output

### 22. Change Management

I learned that project changes should be documented and reviewed.

A change request can include:

* Description of the change
* Reason for the change
* Impact on the project
* Current status

### 23. Task Prioritization

I learned how tasks can be organized based on their importance and urgency.

Common priority levels include:

* Critical
* High
* Medium
* Low

### 24. Project Status

I learned how different areas of a project can be tracked to understand the current project condition.

Examples include:

* Scope status
* Schedule status
* Budget status
* Quality status
* Risk status

### 25. Project Closure

I learned the main activities involved in closing a project.

These include:

* Completing deliverables
* Obtaining customer acceptance
* Closing contracts
* Documenting lessons learned
* Releasing resources
* Archiving project documents

### 26. Project Management Workflow

I learned the general flow of a project:

```text
Project Idea
     ↓
Initiation
     ↓
Requirements
     ↓
Scope Definition
     ↓
Planning
     ↓
Execution
     ↓
Monitoring and Control
     ↓
Testing and Validation
     ↓
Delivery
     ↓
Closure
     ↓
Lessons Learned
```

### 27. Common Project Management Areas

I learned about the major areas involved in managing a project:

* Scope Management
* Schedule Management
* Cost Management
* Quality Management
* Resource Management
* Risk Management
* Communication Management
* Stakeholder Management
* Procurement Management
* Change Management
